2. Purpose

Appointment Scheduler is a web application for management staff at A Real Company Inc to organize and manage appointments with outside contacts and internal employees. The app will allow users to securely log in, view appointments in a calendar interface, manage contact information, and create, edit, or delete meetings.

We chose this product because the client specifically needs a simple way to manage meetings, quickly access contact details, and view schedules by day. In the initial client report, Jimmy Brown requested support for usernames and passwords, CRUD operations for contacts and events, a calendar view for browsing events, and a sidebar that displays known contacts. Our plan addresses those needs directly by combining scheduling tools, contact management, and a clean interface with default dark mode and an optional light mode.

3. Data Description

Table 1: users

We need this table to store the staff accounts that can log in and use the application.

This table stores each user's login credentials and basic account details.

Field Name Data Type Notes
user_id INT AUTO_INCREMENT Primary Key
username VARCHAR(50) Unique login name
password_hash VARCHAR(255) Stores hashed password, never plain text
full_name VARCHAR(100) User display name
email VARCHAR(100) Work email
created_at DATETIME Account creation timestamp

Table 2: contacts

We need this table so users can store and manage the people they schedule meetings with.

This table stores contact details for outside contacts and employees relevant to appointments.

Field Name Data Type Notes
contact_id INT AUTO_INCREMENT Primary Key
name VARCHAR(100) Contact full name
company VARCHAR(100) Organization name if applicable
email VARCHAR(100) Contact email
phone VARCHAR(20) Contact phone number
notes TEXT Optional notes about the contact
created_by INT Foreign key to users.user_id

Table 3: events

We need this table to store each appointment shown on the calendar and event views.

This table stores meeting dates, times, titles, descriptions, and ownership information.

Field Name Data Type Notes
event_id INT AUTO_INCREMENT Primary Key
user_id INT Foreign key to users.user_id
title VARCHAR(120) Meeting title
description TEXT Optional meeting description
location VARCHAR(120) Meeting location or room
start_time DATETIME Appointment start
end_time DATETIME Appointment end
created_at DATETIME Creation timestamp

Table 4: event_contacts

We need this table because one event may involve multiple contacts, and one contact may appear in multiple events.

This table stores the relationship between appointments and contacts.

Field Name Data Type Notes
event_contact_id INT AUTO_INCREMENT Primary Key
event_id INT Foreign key to events.event_id
contact_id INT Foreign key to contacts.contact_id

4. Functions Performed by the App

Function Description Database Effect / Implementation
User login Allows authorized staff to log into the system securely. SELECT from users to verify credentials; password checked against hashed value; session created on server.
View calendar Displays appointments in a calendar/day view. SELECT from events for the logged-in user; client-side rendering with JavaScript calendar component.
Create event Lets the user add a new appointment with time, title, and linked contacts. INSERT into events and INSERT into event_contacts for any selected contacts.
Edit event Lets the user change event details such as title, time, location, or linked contacts. UPDATE events and possibly DELETE/INSERT rows in event_contacts to refresh contact links.
Delete event Removes an appointment that is no longer needed. DELETE from event_contacts first, then DELETE from events.
View contact list Shows a sidebar or page containing known contacts. SELECT from contacts; JavaScript updates the sidebar dynamically.
View contact details Shows full information for a selected contact when the user clicks on them. SELECT from contacts by contact_id; details displayed in modal or detail panel using JavaScript.
Create contact Adds a new contact to the system. INSERT into contacts.
Edit contact Updates an existing contact's information. UPDATE contacts.
Delete contact Removes a contact from the system. DELETE from event_contacts for that contact, then DELETE from contacts.
Toggle dark/light mode Allows the user to switch between default dark mode and optional light mode. Client-side JavaScript toggles a CSS class on the page and may save preference in localStorage.

8. Client Feedback

When we presented our idea, the client emphasized several important features and design preferences.

“Client want a default dark mode with light mode option.”

Based on this feedback, we made dark mode the default visual style and added a client-side light mode toggle.

“Should have sidebar with known contacts to see quickly who they have a meeting with.”

Based on this suggestion, we added a sidebar contact list to the dashboard and made contact visibility a core part of the layout.

“Should have a calendar view to be able to see meetings on days.”

In response, we made the calendar/day view one of the main features of the application rather than just a secondary page.

“Should be able to CRUD contacts and events with contacts.”

This led us to include full create, read, update, and delete functionality for both contacts and events, along with a linking table between them.

Overall, the client's feedback confirmed that our initial idea was on the right track, but it also helped us refine the plan by making the contact sidebar, calendar view, and dark mode requirements more central to the application design.
